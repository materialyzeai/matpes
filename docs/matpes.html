matpes.cli module

This module implements a CLI for MatPES, a material property exploration suite.

The CLI provides the following features: - Download functionality to fetch data related to specific functionals using the download command. - Data processing capabilities using the data command, including filtering MatPES data by

chemical systems or formulas. Both JSONL and Parquet files are supported.

  • Conversion of JSONL files to the flat Parquet format using the convert command.

The commands are structured as subcommands, facilitating distinct functionalities for data retrieval and post-processing operations.

get_data_subset(args)[source]

Filter MatPES data by chemical system or formula.

This function processes a given JSONL file containing MatPES data and filters the entries based on chemical systems or formulas specified by the user. The filtered results are then written to an output file.

Parameters:

args –

Namespace A namespace object containing the following attributes:

  • filename: List[str]

    List containing the name of the input file to process (only the first entry is used).

  • outfile: str

    Name of the output file to write the filtered results to. Defaults to ‘filtered.parquet’.

  • chemsys: List[str]

    List of chemical systems (e.g., ‘Li-Fe-O’) to filter by. If empty, no filtering by chemical system is applied.

  • formula: List[str]

    List of formulas (e.g., ‘Fe2O3’) to filter by. If empty, no filtering by formula is applied.

Returns:

None

Notes

  • The chemical system string should follow the format ‘Element1-Element2-…’.

  • Formulas are case-insensitive and automatically converted to their reduced forms for comparison.

  • Multiple chemical systems or formulas are combined with OR; chemsys and formula filters with AND.

  • Input and output can be JSONL (zopen handles gzip by extension) or Parquet, chosen by suffix. JSONL input can be written as Parquet, but not vice versa.

matpes.convert module

Convert MatPES data into pymatgen Structures, ASE Atoms, MatGL datasets and LMDB databases.

All functions accept a MatPES Parquet file, a legacy .jsonl/.jsonl.gz file or an in-memory pyarrow.Table, and optional column filters (see matpes.parquet.iter_batches()). For example:

import pyarrow.compute as pc
from matpes.convert import to_structures, to_mgl_dataset

structures = to_structures("MatPES-R2SCAN-2025.3.parquet", filters=pc.field("chemsys") == "Li-O")
dataset = to_mgl_dataset("MatPES-R2SCAN-2025.3-train.parquet", include_stress=True)

Optional dependencies: ase for row_to_atoms(), matgl for the MatGL helpers and lmdb for the LMDB helpers (pip install "matpes[ase,matgl,lmdb]").

Layout: key str(i).encode() for i in range(n) maps to a pickled row dict (numpy arrays for numeric per-atom columns, as from matpes.parquet.iter_rows()); b"__len__" holds n and b"__metadata__" a JSON description.   • map_size – Maximum database size in bytes. Sparse on Linux/macOS, so the 1 TiB default costs nothing.

matpes.data module

Methods for working with MatPES data downloads.

Layout of the Hugging Face dataset repository (materialyze/matpes). Each release is a git tag (v2025.3, …); main holds only the latest release, as Parquet:

  • pbe/{train,validation,test}.parquet and r2scan/{train,validation,test}.parquet: the dataset as a random 90/5/5 split. The full dataset is the union of the three files.

  • atoms/{pbe,r2scan}.parquet: isolated-atom reference energies.

Releases before 2025.3 are only available as JSONL, with flat file names such as MatPES-PBE-2025.2[-train|-valid|-test].jsonl, at their own tags. download() resolves the right revision and files.

get_data(functional: Literal['PBE', 'R2SCAN'] = 'PBE', version: str = '2025.3', return_data: bool = True, download_atoms: bool = False, fmt: Literal['jsonl', 'parquet'] = 'parquet', split: Split | None = None) → tuple[list[dict], list[dict]] | list[dict] | None[source]

Download and load a MatPES dataset as a list of record dicts, each with a serialized pymatgen structure.

The return value has the same layout as in matpes <= 0.0.3 whichever file format is downloaded:

  • fmt="parquet" (default): downloads the Parquet files and rebuilds the records from them (see matpes.parquet.row_to_record(); derived fields such as symmetry are not regenerated). The full dataset is returned in train, validation, test order. Releases without Parquet files quietly fall back to JSONL.

  • fmt="jsonl": downloads the JSONL file and returns its records verbatim (2025.1 and 2025.2 only).

For columnar access, which is much faster and lighter on memory, use the Parquet files directly, e.g., matpes.parquet.read_table(download(...)) or the helpers in matpes.convert.

Parameters:

  • functional – “PBE” or “R2SCAN”. Defaults to “PBE”.

  • version – Release. Defaults to LATEST_VERSION.

  • return_data – Whether to load and return the data. If False, the files are only downloaded.

  • download_atoms – Whether to also download and return the isolated-atom reference energies.

  • fmt – “parquet” (default) or “jsonl”.

  • split – Optional “train”, “valid”/”validation” or “test” split instead of the full dataset.

Returns:

The dataset, or a tuple of (dataset, atomic reference energies) if download_atoms is True. None if return_data is False.

matpes.parquet module

Parquet format for MatPES.

MatPES records are stored as flat, Arrow-native columns rather than as serialized Structure.as_dict() blobs, so that readers get columnar projection, predicate pushdown on row-group statistics, zero-copy access to numeric arrays and good compression. One row is one structure. The columns (units in brackets) are:

Convert a flat row back into a legacy-style MatPES record with a serialized structure.

The stored fields are restored, plus the cheaply derived elements, nelements, composition, composition_reduced, formula_anonymous, volume, density_atomic and abs_forces. symmetry, density and builder_meta are not regenerated.

Dict in the layout of a MatPES JSONL record.

write_parquet(rows: Iterable[dict] | pa.Table, path: str | PathLike, metadata: dict[str, Any] | None = None, row_group_size: int = 10000, compression: str = 'zstd') → int[source]

Write rows conforming to SCHEMA to a Parquet file, streaming in row groups.

Parameters:

  • rows – Iterable of row dicts (e.g., from record_to_row()) or a pyarrow.Table.

  • path – Output path.

  • metadata – Extra entries for the MatPES file-level metadata (e.g., {"version": "2025.3"}).

  • row_group_size – Rows per row group. ~10k rows keeps row groups well below the Hugging Face viewer limits while retaining effective statistics-based pruning.

  • compression – Parquet compression codec.

Pages are cut with content-defined chunking, so that a new release that leaves most rows unchanged shares most of its bytes with the previous one and Hugging Face’s deduplicating storage uploads only the changed parts.

Returns:

Number of rows written.
